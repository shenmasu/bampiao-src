# 半瓢 · 用本机订阅出图

一个常驻在本机的出图服务：专用浏览器（干净 profile）+ 任务队列 + 本地面板。
**命令本身是同步的**（出了图才返回），不要自己轮询、也不要 sleep 猜时间；
能并行就在后台跑、估好时间回来收，见下面「等待」。

## 用哪个账号

用户有多个账号时，**默认按「今天出图最少的优先」自动挑**（两个号的额度会一起用）。
他明确说了用哪个号，就加 `--account`：

```bash
bampiao gen "画一张水墨小猫" --out ~/Desktop/cat.png --account 英子
```

`--account` 后面填引号里的账号 **id 或显示名**都行；不知道叫什么就先跑 `bampiao usage` 看一眼。

**什么时候该主动指定**：用户说"用第二个号""别用那个号""这个号额度要紧留着"。
他没说的时候不要自己指定——让默认策略去均摊，否则又变回"永远只有一个号在干活"。

## 什么时候用它

- 用户要一张图：图标、插画、贴图、剪影、参考图改图
- 用户要一批同风格图（6 张以上），希望排队慢慢跑
- 用户问"今天出了几张 / 哪个账号在冷却 / 撞上限了没"

**不要**用它：需要精确文字排版的海报、需要真实照片的场景、用户明确说要用某个别的工具。

## 三条主命令

```bash
# 一条图，立刻出（阻塞到文件落盘）
bampiao gen "1024x1024 图标：米白底，中央赭橙实心圆，扁平矢量，无文字" --out D:\art\icon.png

# 改图：带参考图
bampiao gen "改成冷色调，保留构图" --out D:\art\icon2.png --ref D:\art\icon.png

**动图（GIF）**：ChatGPT 网页版 Images 2.6 已支持，直接 `--gif`。
- 交付物会是 `.gif`；即使 `--out` 写的是 `.png`，也会按真实内容改名成 `.gif`。
- `--json` 里有 `animated` / `frames` / `format`，agent 不用自己开文件判断。
- GIF 分辨率通常比静图小（常见 358×358），这是正常的；`--alpha` 对动图会跳过抠图。
- 只有明确要动图才加 `--gif`；不加时模型给静图或 GIF 都按真实内容保存。

**矢量（SVG）**：`--svg` 要静态矢量文件，`--svg-anim` 要**会动的 SVG**（文件内嵌 SMIL / CSS 动效）。
- 交付物是 `.svg`（XML 文本），不是位图；`--out` 写 `.png` 也会按真实内容改名成 `.svg`。
- 网页版把它当**文件附件**交付，不是聊天里的图片。半瓢会自动取回附件并落盘。
- 这不是 OpenAI 官方的「SVG 动图」格式：官方 API 的 `output_format=svg` 是静态矢量，动图走 `gif`；
  这里会动的 SVG 是网页版用代码写出来的、自带动画标签的矢量文件，浏览器打开就能看到动效。
- `--json` 里有 `format="SVG"` / `svg` / `svg_animated`；`animated` 恒为 `false`（那是给 GIF 帧用的）。
- `--svg` 与 `--gif` 互斥；`--alpha` 对 SVG 会忽略（矢量天然透明）。
- SVG 可无限缩放、改色，适合图标 / UI 组件 / 插画；不适合需要照片质感的画面。

# 成批：写 JSON 再投单（推荐，能一次投 6–16 张）
bampiao submit --shots shots.json --brief "角色立绘第一批" --tag 角色
bampiao run --once          # 把队列跑完就退出
```

`shots.json` 的形状：

```json
[
  {"id": "S01", "prompt": "…", "aspect": "1:1", "alpha": false, "refs": ["D:\\art\\ref.png"]},
  {"id": "S02", "prompt": "…", "aspect": "2:3"}
]
```

## 出图不满意怎么办（**别傻等，这是被支持的正常操作**）

半瓢不会自己"变好"。看到结果后**必须自己判断要不要重来**，然后主动开新的一单：

| 你的判断 | 怎么做 | 为什么 |
|---|---|---|
| 大体对，只有局部不对（颜色 / 某个物件 / 表情 / 多了一只手） | `bampiao gen "<只说要改哪里>" --out b.png --ref a.png` | 带原图当参考，构图和风格能保住，不会整张重画 |
| 构图或主体就不对，等于重画 | 用**重写过**的提示词开新 `gen`；只有想延续风格才带 `--ref` | 带 ref 会让模型倾向复刻旧构图，想推翻的东西反而被拖着 |
| 拿不准要哪种 | 一次投 3–4 条不同写法（`submit` 多 shot）挑一张 | 比反复单张试更快，额度也更可控 |

**几个反直觉但重要的点：**

- 「不满意」**不是失败**，不要当错误上报给用户，也不要因此停下。重开一单就行。
- **别拿同一条提示词反复重投**：出来的还是那样，白烧额度。要重试就**改一个变量**
  （措辞、`--aspect`、`--ref`）。
- 重投产生的是**新单号**；旧单和旧图都留着，用户要对比，别删。
- 局部修**必须带 `--ref`**：不带就是重新构图，改动会跑到别的地方去。

## 等待：一次 `gen` 是 1–3 分钟的阻塞调用

`gen` 一直阻塞到文件落盘或超时（默认 600 秒）。两种正确姿势，按你的能力选：

**① 你只能顺序做事** —— 直接等它返回，返回后**先看结果**，再决定下一步。
不要 sleep 几秒去 `jobs` 轮询：`gen` 自己就在等，轮询纯属噪音。

**② 你能并行** —— 放后台跑，同时干别的，估两分钟左右回来收：

```bash
bampiao gen "1024x1024 图标：…" --out a.png &
# … 去做别的事（改代码、写文档、准备下一批提示词）…
wait            # 回来收结果
```

成批（6 张以上）用 `submit` + `run --once`，**不要**在循环里逐张 `gen`——
那会串行占住同一个账号，还不如排队。

**绝对不要**：自己写轮询循环读"进度"（没有进度接口）；没出结果就说"已完成"；
把 `TIMEOUT_UNCERTAIN` 当失败重投（远端可能已经出图，重投＝重复烧额度）。

## 提示词：**你自己写**，别问用户要

用户只会说"画个猫"，剩下的是你的活。写法按这个顺序凑齐：

1. **尺寸 / 比例** —— 写进提示词开头，并且和 `--aspect` 保持一致
   （`1:1` 图标和头像、`16:9` 横图封面、`2:3` 立绘海报、`9:16` 手机壁纸）。
2. **主体** —— 一句话说清是什么、在干什么、朝向哪边。
3. **风格** —— 扁平矢量 / 厚涂 / 铅笔线稿 / 电影感光比 / 像素风。**只选一种**，
   混着写会得到四不像。
4. **构图与留白** —— "居中"、"三分法"、"主体占画面 60%"、"四周留白"。
5. **不要什么** —— 写进提示词而不是指望 `--aspect`：`无文字`、`无水印`、`不要边框`。
   （模型的文字排版很差，需要字就后期加。）

```bash
# 好：一眼能看出要什么
bampiao gen "1024x1024 应用图标：米白背景，正中央深绿色实心圆，扁平矢量，粗轮廓，无文字" \
  --out icon.png --aspect 1:1
```

**几个经验值：**

- 图标类加 `粗轮廓`、`无渐变`，缩到 16px 还认得出。
- 要透明底用 `--alpha`（它会自动追加洋红底要求，事后抠像），别自己在提示词里写 `透明背景`。
- 改图必须 `--ref`，并在提示词里说**只改哪一处**（"把圆改成蓝色，其余不变"）。
- 一次想要多张不同风格 → `submit` 投 3–4 条，别指望一条里面变出花。

## 投单与队列：什么时候会返回

| 你用的 | 行为 | 什么时候用 |
|---|---|---|
| `gen` | **阻塞**到出图或超时（默认 600 秒）；`--gif` 出循环动图，`--svg` / `--svg-anim` 出矢量文件 | 1–3 张、要马上拿到文件 |
| `submit` + `run --once` | 投单立刻返回；`run --once` 阻塞到**队列跑空** | 6 张以上、同风格批量 |
| `submit`（不跑） | 只入队 | 交给常驻的桌面壳慢慢跑，你继续干别的 |

- `submit` 支持 `--request-id`：**同一个值不会重复建单**，网络超时后重试安全。
- 同一账号**不要并行**：两个进程连同一个 CDP 页面会串图并重复烧额度。
  要并行就加账号（上限由 `concurrency` 决定，默认 2）。
- `run --once` 的退出码 `6` 表示**部分成功**，去 `jobs --json` 看哪几条失败。

## 异常：先看现象，再看错误码

**没有错误码的（环境类问题）：**

| 现象 | 判断依据 | 你该做什么 |
|---|---|---|
| 浏览器起不来 | `browser status` 不是 running | `bampiao browser down <账号>` 再试一次，仍不行就报错 |
| 端口被占 / 卡死 | `doctor` 报端口异常 | **别手杀进程**，用 `bampiao browser down` |
| 你猜不出原因 | — | 跑 `bampiao doctor` 和 `bampiao feedback`，把包给用户 |

**有错误码的，按下面那张「失败处置」表决策**（`AUTH_REQUIRED` / `QUOTA_COOLDOWN` /
`RENDER_FAILED` / `TIMEOUT_UNCERTAIN` / `NO_LANE` / `BUSY` / `NO_REF_FILE` / `BROWSER_LOST`）
——这里不重复一遍。

**红线：连续两次同样的失败，就停下来问人。** 不要把额度耗在同一条路上。


## 交活之前自检

1. 文件真的存在吗？`ls -l` 看一眼，**不要凭退出码 0 就宣布完成**。
2. 尺寸对不对？要 1:1 出来的却是 16:9，说明 `--aspect` 和提示词打架了。
3. 图给用户看了吗？给出**文件路径**，能贴图就贴图。
4. 重投过的话，把"第几次、为什么重投"说一句，用户才知道你干了什么。

## 会话堆太多了怎么办

每出一轮图就会在 ChatGPT 侧栏留一个会话，久了会堆成几百条。清理只动**半瓢自己开的**
（出图时记了名单），用户自己聊的一条都不碰：

```bash
bampiao chats list -n 30              # 列出来，标 * 的是半瓢的
bampiao chats rm --keep 10 --yes      # 半瓢的只留最近 10 条
bampiao chats rm --older 7 --yes      # 删 7 天前的
bampiao chats rm --id <会话id> --yes  # 删指定的
```

删除不可撤销（等于侧栏里点删除）。**不要替用户决定**：先 `list` 给他看，
数量大就问一句，别自己 `--yes` 一路删下去。

## 看一眼状态

```bash
bampiao usage        # 每个账号：今天几张、登录态、冷却剩余
bampiao jobs         # 最近的单与状态
bampiao show 12      # 某一单的明细
bampiao ui           # 打开面板窗口
```

## 全部命令都支持 `--json`

`--json` 时 **stdout 永远只有一行 JSON**——成功是结果，失败是 `{"ok": false, "error_code": ..., "why": ...}`。
可以直接 `json.loads`，不用先判断空输出。退出码是合约的一部分：

| 码 | 含义 | 你该做什么 |
|---|---|---|
| 0 | 成功 | — |
| 2 | 参数 / 配置错 | 改命令，别重试 |
| 3 | 需要用户动作 | 去登录 / 加账号 / 装浏览器，**不要重试**，先把人叫来 |
| 4 | 等待超时 | **别重试**：图可能已经出来了，先去网页/面板确认 |
| 5 | 内部错误 | 可以重试一次，再不行看日志 |
| 6 | 部分成功 | 看 `jobs --json` 里哪些条目失败 |

## 失败处置（**错误码是固定的，按它决策**）

| 错误码 | 含义 | 正确做法 |
|---|---|---|
| `AUTH_REQUIRED` | 掉登录了 | 告诉用户跑 `bampiao login <账号>`，**不要重复投单** |
| `QUOTA_COOLDOWN` | 撞生成上限 | 等冷却（`usage` 里有剩余分钟），**不要重试** |
| `RENDER_FAILED` | 出图失败（网页改版 / 质检不过） | 可以重投一次；连续失败就报给用户 |
| `NO_LANE` | 没有可用账号 | 让用户加账号或等冷却 |
| `TIMEOUT_UNCERTAIN` | 发出去之后断了，远端可能已出图 | **绝对不要自动重投**——会重复出图、重复烧额度。让用户去面板确认 |
| `CANCELLED` | 人为取消 | — |
| `BUSY` | 同一账号正忙 | 稍后再试（别并发同账号） |
| `NO_REF_FILE` | 参考图路径不存在（文件没生成好 / 路径写错） | 去查文件，**改提示词没用**；文件就位后重投一次 |
| `BROWSER_LOST` | 出图时浏览器被关掉了 | 重投一次；反复出现就报给用户 |

## 硬规矩

1. **绝不用 Codex 内置生图**（`$imagegen` / `image_gen`）——那吃的是 Codex 额度，
   而这个工具存在的意义就是用网页订阅额度。Codex 那边的开关已经被物理关闭，别去开。
2. **不碰用户的日常浏览器**。每个账号一个专用 profile，路径由配置决定；
   不要自己去操作 Chrome 的 `User Data`。
3. **同一账号不要并行出图**：两个进程连的是同一个 CDP 页面，会串图并重复烧额度。
   要并行就加账号（并发上限由 `concurrency` 控制，默认 2）。
4. **投单用 `--request-id` 做幂等**：同一个值不会重复建单，重试安全。
5. 用户没有明确授权时，**不要动他们的账号**（登录、备份、删除）。

## 排障

```bash
bampiao doctor              # 环境自检：依赖、浏览器、账号、端口
bampiao probe acc1          # 这个账号现在停在登录页还是对话页
bampiao browser status      # 浏览器实例状态（不知 pid 就别手动 kill）
```

`doctor` 有 `✗` 就先修它，别绕过。日志在 `~/.bampiao/logs/`。

## 另外：文本任务（`bampiao ask`）

出图之外，半瓢还能把文字活儿交给同一个号池去答。**走的就是你的会员额度**，和出图共用账号，一条一条来。适合"活儿长、要跑几分钟、你自己上下文快满了"的时候。

```bash
bampiao ask "把这个需求拆成三步，每步一句话"      # 结果直接打到 stdout
bampiao ask --file 需求.md --out 方案.md         # 读文件、写到文件
bampiao ask --json "..."                        # 只输出一行 JSON
```

- 默认超时 300 秒，长任务加 `--timeout 900`
- 它**看不到图**，别让它判断画面好坏
- 和出图同一个号池；一条一条来，别并发（会抢输入框）
- 用户说「这段交给 codex」时，就是让你跑这条命令
